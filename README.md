# SDEV2301 Workbook Repository

This repository is your personal **SDEV2301 workbook** for examples, practice, and experimentation completed throughout the course.

> [!IMPORTANT]
> This repository does **not** contain assignment instructions or assignment starter projects.
>
> All assignment specifications, starter projects, submission instructions, and due dates are provided separately through **Brightspace**.

## What belongs in this repository

Use your workbook for work that is **not submitted as a graded assignment**, including:

- Examples completed during class
- Code demonstrated in course slides
- Practice exercises
- Your own experiments with concepts covered in class
- Small projects created while learning or troubleshooting

> [!WARNING]
> Do **not** clone the course template repository directly. Create your own repository using **Use this template** first, and then clone your newly created repository.

## Create Your Workbook Repository

This repository was created from the course-provided **SDEV2301 Workbook Template**.

To create your workbook:

1. Open the SDEV2301 Workbook Template provided by your instructor.
2. Select **Use this template → Create a new repository**.
3. Select your personal GitHub account as the owner.
4. Name the repository:

   `SDEV2301-Workbook`

5. Choose either **Public** or **Private** visibility.
6. Create the repository.
7. Clone **your newly created repository** to your computer.
8. Open the repository in Visual Studio and add projects as we work through the course.

Do not clone the course template directly.

## Repository Visibility

You may make your workbook either **Public** or **Private**.

### Public Repository

A public repository is the simplest option when asking the instructor to review or help troubleshoot your code.

Send the instructor the URL to your repository when assistance is required.

### Private Repository

You may keep your workbook private if you prefer.

If the repository is private, grant the instructor access using the GitHub username provided in the course:

**Settings → Collaborators → Add people**

The instructor must have access before a private repository can be reviewed.

Both Public and Private repositories are acceptable for SDEV2301.

## Git Workflow

Use the workbook throughout the term rather than treating it as temporary storage.

You are encouraged to:

- Commit after completing meaningful pieces of work
- Use descriptive commit messages
- Push your commits to GitHub regularly
- Keep examples from different lessons organized
- Experiment freely—you can always use Git history to return to an earlier version

Example commit messages:

```text
Add Lesson 03 decision structure examples
Complete methods practice exercises
Add Product class example from Lesson 05
Fix validation example from class
```

## Suggested Organization

Organize your work by lesson or topic as the course progresses. For example:

```text
SDEV2301-Workbook/
├── Lesson01/
├── Lesson02/
├── Lesson03/
├── Lesson04/
└── README.md
```

Individual lessons can contain one or more Visual Studio solutions or projects.

Your instructor may recommend a more specific structure during class.

## Protect Your Information

Never commit:

- Passwords
- GitHub personal access tokens
- API keys
- Private connection strings
- Authentication credentials
- Personal or confidential information

If you accidentally commit a credential, deleting the file in a later commit does **not** remove the credential from Git history. Revoke the credential immediately and notify your instructor if you need assistance.

## Getting Help

When asking for help with workbook code, provide:

1. A link to your GitHub repository
2. The lesson/project you are working on
3. A brief description of the problem
4. Any relevant error message

Keeping your workbook pushed to GitHub makes it much easier to review your code and troubleshoot problems.
